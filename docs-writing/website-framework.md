# Nebula Lab 网站信息架构与内容框架

整理日期：2026-10-22。

用途：指导官网、用户手册和后续页面设计。本文件是内容规划，不是已经上线的页面，也不是新的产品功能承诺。

事实基线：2026-10-21 对主仓库代码、权限契约、开放任务及发布记录的阅读。已核对的发布基线为正式版 v0.9.1、Beta v0.9.2-beta.1；设计实施或上线前需要重新核对。未运行桌面软件、未核实生产服务开关。

## 1. 网站要让访问者理解什么

产品定位建议：

> 把配方、样品、测试数据和分析成果串起来的科研桌面工作站。

首页主标题候选：

> 从配方到成果，让每一步都有据可查。

说明文案候选：

> 记录物料与配方、样品制备和测试数据，复用成组处理流程，并与 Origin 衔接作图。通过成果归档保留来源与版本；需要实验室服务器的功能，按接入条件和数据权限使用。

上述是整体产品方向的表达。每个模块必须标记发布状态与使用前提，尤其是 Beta 成果归档、成果上报和实验室接入能力。

访问者应该依次得到五个答案：

1. 这是做什么的软件，适不适合我的实验工作？
2. 一次实验从配方到成果，信息怎么连起来？
3. 哪些工作在本地做，哪些需要 Origin 或实验室服务器？
4. 我现在能用哪些能力，需要什么账号或权限？
5. 去哪里下载，第一次如何完成一个任务？

## 2. 业务骨架

主线：

```text
物料库 → 基础配方 → 样品制备 → 测试记录 → 成组数据处理
                                              ↓
                                      Origin 分析与作图
                                              ↓
                                   成果归档、版本和来源追溯
```

实验室数据中心作为样品、测试和成果的上报、受控读取与检索层；社区作为流程、模板、脚本、插件等资源交流层。两者分别说明，不能合并成“云端共享”。

这条主线表达典型任务，不要求用户先录完所有实验信息才能处理一个电脑文件。

| 阶段 | 用户做什么 | 留下什么 | 下一步如何关联 |
| --- | --- | --- | --- |
| 物料 | 查询或手动录入材料、物性、供应商与牌号等 | 可复用的材料记录 | 配方和样品组成选择物料 |
| 配方 | 选择物料，配置比例、输入与计算公式 | 基础配方、版本和用量信息 | 样品引用版本并形成自己的配方草稿 |
| 制备 | 调整本次用量，填写步骤、工艺备注及适用的组成信息 | 样品及确认后的制备快照 | 测试挂到具体样品 |
| 测试 | 添加项目、日期、方法、仪器、操作人、指标和文件 | 多条测试记录、结果指标、原始文件 | 选择文件加入处理工作区 |
| 处理 | 确认列与单位、归组，配置或复用处理步骤 | 处理结果、流程配置和来源记录 | 选定数据推送 Origin |
| 作图 | 在 Origin 中分析、调整并保存工程 | Origin 工程与正式图像 | 选择归档或更新成果版本 |
| 归档 | 保存工程、图像，复核输入来源 | 可追溯的成果和版本 | 从参与样品、测试反查成果 |
| 数据中心 | 经确认上报，按权限检索和获取 | 实验室服务器上的记录、修订与文件 | 按既有规则读取和复用 |

## 3. 官网、文档和管理界面的职责

| 页面体系 | 服务对象 | 核心任务 |
| --- | --- | --- |
| 官网 | 初次了解产品的人、准备接入的实验室 | 解释价值、工作流程、实际能力、接入前提和下载方式 |
| 用户文档 | 正在操作桌面软件的成员 | 按任务提供准确步骤、按钮名称、异常处理与下一步 |
| 管理员指南 | 管理成员、设备和服务器的人 | 解释接入、角色、审批、运行维护及权限边界 |
| 软件内管理工作区 | 已获管理资格的用户 | 执行实际管理操作；不由官网页面替代 |

官网默认不新增实验数据上传、账号管理或科研数据浏览入口。若以后要建设网页业务客户端，需要单独定义需求、认证和授权范围。

## 5. 首页内容顺序

### 01 首屏：产品是什么

- 主标题：从配方到成果，让每一步都有据可查。
- 一段简短说明，突出桌面工作、来源关联与 Origin 衔接。
- 主按钮：下载桌面端。
- 次按钮：查看完整流程。
- 短说明：Windows；实验室功能需相应接入；不同版本能力以发布说明为准。
- 配一张真实桌面工作区截图。若是概念关系图，应明确其为示意图。

### 02 完整流程：它如何服务一次实验

分为“记录实验 / 处理数据 / 保存成果”三个阶段，展示六个节点：

1. 物料与配方。
2. 样品与制备。
3. 测试与原始文件。
4. 分组与统一处理。
5. Origin 交接。
6. 成果归档与追溯。

每个节点说明留下什么；详细操作进入工作流程页或文档。桌面可横向排布，手机按阅读顺序纵向排列。

### 03 三项核心价值：为什么需要它

- 少做重复整理：同类数据归组，复用已验证的处理流程。
- 找得到实验依据：从图和工程反查样品、测试、配方版本与制备信息。
- 保留可继续使用的成果：工程、图像与版本一起收录，而非散落在文件夹里。

不使用未经测量的节省百分比、毫秒级、几秒处理数万行等性能承诺。

### 04 真实场景：单变量对照实验

使用明确标注为“演示数据”的 A/B/C 三个样品示例，展示：

```text
选择不同配方对应的同类测试文件
→ 核对列、单位和实验条件
→ 应用一致处理流程
→ 推送 Origin 比较
→ 收录成果并查看来源
```

单变量关系由研究者确认；页面不暗示软件自动完成实验设计、因果判断或科学结论生成。

### 05 本地与实验室：数据在哪里，谁能使用

用两栏解释用户电脑与实验室服务器，再单列社区资源。

- 用户电脑：日常录入、计算、处理和本地成果保存。
- 实验室服务器：上报、检索、受控读取、审计与服务器备份。
- 社区：流程、Origin 模板、脚本和插件等协作资源。

正文优先讲用户能理解的用途，数据库、组网组件和技术栈放到架构或管理员文档。

### 06 真实界面与开始使用

按前面的任务顺序展示界面，并提供“完成第一次数据处理”和“了解实验室接入”的入口。

正式版和 Beta 下载状态从发布记录核对；截图须标明对应版本。远期科研助手、PPT 生成等进入路线图，不占首页主功能区。

## 6. 用户手册的分组

### 开始使用

- 安装与实验室接入。
- 核心概念：物理样品、工作区数据项、配方、工程、成果。
- 两条上手路线：直接处理电脑文件；从配方和样品开始记录。

### 记录实验

- 物料与物性。
- 基础配方、公式和版本。
- 样品配方与制备确认。
- 制备步骤、组成与工艺。
- 测试项目、结果指标和原始文件。

### 处理与作图

- 导入与解析设置。
- 分组、数据列与单位。
- 处理步骤、流程模板和批量复用。
- 曲线预览与 Origin 导出。
- 保存和打开 `.nbp` 工程。

### 归档与检索

- 本地成果归档。
- 在 Origin 编辑后更新成果版本。
- 成果来源和参与样品。
- 数据中心上报、检索、下载与访问申请。
- 本地备份、恢复与版本兼容。

### 管理与扩展

- 成员和设备接入。
- 样品共享、访问审批与角色边界。
- 词表治理。
- 插件、社区资源、设置与故障排查。

先提供能执行的基础路径；尚未核实或未交付的操作不编写成教程。

## 7. 必须讲准确的行为与权限

| 容易误解的表达 | 对外应说明的事实 |
| --- | --- |
| 选物料就自动生成最优配方 | 计算依据用户配置的规则和输入，不自动完成实验设计 |
| 制备参数都已结构化 | 主界面制备步骤主要是顺序文本和备注；部分组成与工艺已有专门字段 |
| 上传测试文件自动获得全部指标 | 原始文件、结果指标分别保存；自动提取取决于支持的格式与流程 |
| 基础配方修改后所有样品同步变化 | 部分未改动草稿可跟进；确认制备的历史快照不随之改写 |
| Origin 每次修改都会自动回写 | 修改后保存工程，再在成果入口手动更新版本；不是把图贴入备注 |
| 上传数据中心就是共享给全组 | 上传、数据可见性与成果权限分别判断 |
| 所有成员可读取已上传成果 | 当前云端成果为创建者私有，样品可读不自动授予成果读取权 |
| 成果归档只有管理员能做 | 普通成员在具备许可及相关数据权限时也可操作 |
| 管理员默认能看所有私有成果 | 管理角色不自动绕过私有成果权限 |
| 支持多端实时协同编辑和双向同步 | 当前不能据此承诺；换机恢复可编辑业务记录仍有独立讨论任务 |
| RAG、PPT 自动生成已可用 | 属于规划或讨论内容，单独放路线图 |

成果来源存在多人数据时，应专门解释：能读取、能导出、能本地分析，不等于能再次上传发布。

## 8. 状态标识与截图需求

发布状态和使用前提分别标注，避免用一个“可用”覆盖所有条件：

- 发布状态：正式版 / Beta / 开发中 / 规划中。
- 使用前提：需要 Origin / 需要实验室接入 / 受相关数据权限限制。

首批需要的真实截图：

1. 物料库及录入。
2. 配方表和计算结果。
3. 样品配方、制备步骤与确认入口。
4. 测试指标、原始文件和添加到数据处理。
5. 分组数据与处理流程。
6. Origin 导出配置。
7. 成果来源、版本与更新入口。
8. 数据中心检索及权限提示。

截图使用合成或获准的演示资料，记录版本与场景。不将未发表实验数据、成员身份或内部运维信息放入官网。缺截图时列为待补，不制作看起来像已交付产品的虚构界面。
