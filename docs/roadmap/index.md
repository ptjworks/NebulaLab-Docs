# 发展方向

Nebula Lab 围绕“物料—配方—制备—测试—处理—Origin—成果”连接实验记录。当前具体交付能力以[正式版及 Beta 发布记录](https://github.com/TshyGO/NebulaLab-Releases/releases)为准；代码已实现不等于已完成安装包或生产验收。

## 持续完善的工作路径

- 维护材料和配方，记录样品制备与测试。
- 将原始文件、结果指标、处理流程和成果来源关联起来。
- 对同类数据复用处理方法，交接 Origin 分析和作图。
- 保存成果与版本，按权限上报和检索实验室数据。
- 改善性能、授权、安装升级和恢复的可靠性。

Origin 是分析与作图的交接点，后续成果归档和来源追溯仍属于产品工作路径；外部工程修改需要手动收录更新。

## 后续 AI 方向

以下内容是规划，尚未作为已交付功能提供，也没有承诺交付时间：

1. **文献主动抓取**：围绕研究方向发现并收集文献线索。
2. **周报汇总与 PPT**：汇集组内成员周报，整理汇报材料，供管理员在授权范围内查阅。
3. **智能体协作**：按成员身份、数据权限和来源记录，调用获准科研数据辅助工作。

查看 [AI 规划](../ai/index.md)了解这些方向。

## 扩展方向

制备信息将继续探索更通用、可复用的模块定义，减少新增研究方向时逐项硬编码的成本。跨设备恢复业务记录等能力，仍需明确数据身份、权限和迁移规则，不能当作已有实时双向同步。
